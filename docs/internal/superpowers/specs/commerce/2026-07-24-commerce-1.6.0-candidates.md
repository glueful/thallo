## The unifying theme: admin-born drafts

Both headline candidates are the same architectural move: **an admin-born entity that exists
immediately but acquires its invariants at a later transition** (product: activate; order:
finalize). Thallo's own entries already work this way (`EntryRepository::createEntry` inserts a
blank entry + empty draft on one click — no title, no slug, junk-draft accumulation accepted
with no GC), so the pattern has an in-house precedent for both the UX and the cost.

## Candidate 1 — Instant product drafts

Today `POST /products` enforces, at creation: unique slug, ≥1 variant for purchasable types
(`CatalogService::validateVariants` — "A product needs at least one variant."), immutable type
once variants exist, and `metadata.external_url` for external. The Omnibox Launcher
(spec §5.4, shipped) collects the minimum atomically. 1.6.0 relaxes creation and moves
enforcement to **activation**:

- Drafts may be **variant-less**; activating a purchasable product requires ≥1 variant.
- Slug seeded with the product uuid (entries' uuid-fallback trick; column stays NOT NULL +
  unique); **activation requires a human slug** — a `products/8fK2mQpL9xTz` storefront URL
  must never go live. Note: the pack's slug-lifecycle authority reserves the uuid placeholder
  at create and ledgers the rename — harmless (never-published slugs), but needs a test.
- **Type stays mutable while draft AND variant-less**; locks at first variant / activation.
- The Launcher survives unchanged and gets faster: Enter creates earlier (no price needed);
  the "type it or tap it" screen becomes a true one-click instant create.
- Unlocks concept C ("Preview-First" — edit the storefront card directly) as a create MODE,
  since media can attach the moment the row exists.
- Accepted cost (like entries): abandoned blank drafts accumulate in the products list.

## Candidate 2 — Manual / draft orders (the Woo "Add new order" gap)

Admins cannot create orders today: `CheckoutService::placeOrder` is the ONLY writer of
`commerce_orders` rows — one transaction fusing server-computed pricing (discount bps,
zone/class shipping, tax rates), atomic CAS stock claims, line inserts, checkout-attempt
idempotency, and the after-commit `OrderPlaced` → webhook/marketplace fan-out. Woo's screen
exists because Woo is permissive (free status dropdown, hand-editable totals, no stock claim
by default) — those are **anti-goals** here, not gaps.

Scope sketch ("checkout operated by an admin, in slow motion"):
- New **draft** order state ahead of `pending_payment`; admin-born entry into
  `OrderStateMachine` (status stays a guarded transition, never a dropdown).
- **Stock**: NOT claimed while drafting; claimed atomically at a **finalize** transition
  through the same `StockRepository` chokepoint; released on cancel exactly like today.
- **Pricing**: lines priced from the live catalog via the pricing engine (server-side
  recalculate); per-line override for comps/negotiated B2B ONLY behind an explicit, audited
  permission — never free-typed totals.
- **Payment**: existing `mark-paid` transition; later, optionally a payvia payment link.
- **Events/webhooks**: fire at finalize (the moment the order becomes real to the outside
  world), with `origin`/actor attribution (admin vs storefront).
- **Guest custody**: manual guest orders need a deliberate access story (the storefront's
  guest_token flow assumed checkout custody).
- API surface: draft-create, line add/update/remove, recalculate, finalize — plus
  `AdminRouteCatalog` entries (restricted hosts must allowlist), OpenAPI, SPA Orders surface
  gaining a create flow.

## Riders / tickets to consider bundling at the same release

- **Storefront order wire projection** (deferred security fix, tracked since 1.4.1):
  `accessCheckedOrder()` returns the raw row minus `guest_token_hash` to CUSTOMERS —
  same internal-column class as the admin leak; fix must project at response boundaries only
  (the helper also feeds `retryPayment` internals).
- **`commerce_stock.tracked/quantity` NOT NULL** ALTER migration (final-review ticket; the
  read-time `StockIntegrityException` guards meanwhile).
- **OpenAPI generator path-order canonicalization** (final-review ticket; regen output is
  route-cache-state-dependent — semantically stable, byte-unstable).

## Prerequisite ordering

Candidate 1 is self-contained. Candidate 2 touches the state machine, stock, and event
fan-out — full spec treatment, opus review on the money paths. If both ship in 1.6.0, the
release story is one sentence: "entities can now be born in the admin as drafts, and the
system's guarantees engage when they become real."

# Visual Builder Phase B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase B of the visual builder: site-owned style classes that blocks compose through the cascade (records, API, admin page, the class layer in the renderer with a consistent generation snapshot, apply/remove/reorder/detach and "save as style class" in the editor, archive and the two everywhere-jobs), and structural editing (nesting depth five, whole-candidate-tree legality shared with the server through fixtures, one drag coordinator with stage, outline and inspector-list adapters, bridge geometry, keyboard "Move to…", the server block factory, sibling multi-select, rejection handling and browser proofs).

**Architecture:** seven release slices. Each lands schema, validator, renderer, API, admin behaviour and tests together and leaves Thallo installable, renderable, editable and green, so any slice can be a beta. Classes arrive server-first (the record, the resolver's class layer and the generation snapshot are inert until the editor writes a reference), then the API and page, then the editor. Structure arrives rules-first (depth five and legality fixtures both runtimes agree on), then the coordinator and its adapters, then multi-select and the proofs. Nothing ships behind a flag: a slice is either complete or not cut.

**Tech Stack:** PHP 8.3 / Glueful 1.85.7, Twig under `TemplatePolicy`, Nuxt UI admin (Vue 3, vitest, `vue-draggable-plus`), PHPUnit, Playwright (Chromium for the builder proofs; Chromium, Firefox and WebKit for the computed-style proofs).

**Spec:** `docs/internal/superpowers/specs/2026-09-14-visual-builder-design.md` (§4 and §5 govern Phase B; §1.6, §3.1, §3.4 and the §3.5 generation invariant are relied on). Section numbers below refer to it. Phase A shipped in beta.30 (`docs/internal/plans/2026-09-14-visual-builder-phase-a-plan.md`); its names are reused verbatim.

## Global Constraints

- **The block tree is the source of truth; the DOM supplies geometry only** (§0.1). No drag moves a block before its drop yields an operation.
- **Breakpoint-first cascade** exactly as §1.6; classes are layers in list order below the instance; the resolver returns a managed value or `theme-default`, never a theme value. Both runtimes read the same fixtures.
- **A style class declares no capabilities or targets.** Applied to a block, each declaration lands only where the block has the capability and is dormant elsewhere; the validator therefore checks a class's `style` against `StyleCapabilities::all()` and a block's `settings.style` against the block's own capabilities, never the other way round.
- **Reference validation checks ownership, not mere existence** (§4.1): an id in `settings.classes` must belong to the site (tenant or workspace) the document belongs to; an archived owned class is a valid reference (old revisions restore), an unknown or foreign id is rejected, a repeated id is rejected.
- **The style generation identifies style-class definitions, nothing else.** Generation N names one exact set of class records for one site. It changes only when a class record is written (create, update, archive, lock, unlock); document rewrites, including the everywhere-jobs, never touch it and invalidate their documents through the ordinary content path.
- **Class mutations and style-generation increments commit atomically** (§3.5), structurally: `StyleClassRepository::write()` opens the transaction on its own connection, runs the row write and the generation increment on that same connection as an atomic `UPDATE … SET generation = generation + 1`, and nothing else can increment. Tests force both failure directions.
- **A render obtains one consistent class snapshot whose generation names it.** The snapshot is loaded once per request from uncached reads; no snapshot is returned unless its before and after generation reads match; exhaustion is a hard failure, never a stale fallback. Response metadata (apply, full-page HTML, bridge acknowledgements, the class-list response) and cache identity describe that same snapshot. The generation is per site: the system-global flag is replaced.
- **Names are site-unique case-insensitively and freely renameable; ids are stable** (§4.1).
- **Document writes are conditional.** Every block-bearing source persists through a conditional update on a `lock_version` the reader handed out, so a concurrent change is a refused write, never a lost one; the class lock is checked inside the document's write transaction against the references the write introduces.
- **Depth counting convention, stated once per runtime:** root list items are depth 1, children 2 (`BlockDepth`, `RenderContextExtension::MAX_BLOCK_DEPTH`, `MAX_BLOCK_DEPTH` in the admin, asserted equal by tests). The five-level composition used everywhere is section → columns → card → container → heading (a button has no slot). A leaf subtree has height 1. A drop is legal when `parentDepth + subtreeHeight <= 5`, where `parentDepth` is the destination parent's depth (0 for the root list). The cap rises from 3 to 5 in B5; until then every formula uses the constant, never a literal.
- **The builder is stricter than the API** (§5.2): the builder always enforces a slot's `block_types` allow-list; `enforce_block_types` remains the server switch and is not touched.
- **Whole-candidate-tree legality before any structural commit**: one complete candidate tree is validated; a multi-selection is normalised to document order with destination indices interpreted against the tree with the moving set removed; a group commits whole or not at all.
- **No legacy code, no compatibility.** Every replacement deletes the old path, its helpers and its tests in the same commit: the same-parent FLIP drag and `thallo:block-move-to` leave when the coordinator's stage adapter arrives; inline `{ data: {}, settings: {} }` block construction leaves when the factory arrives; the Design page's read-only outline becomes the draggable outline. The inspector's outline rail (`BlockOutlineRail.vue`) stays: it serves ordinary `BlocksField` editing outside the Design page, which the coordinator does not reach in Phase B.
- **Two class lists are never both called "Classes"** (§3.4): the ordered style class list is labelled "Style classes"; `advanced.css_classes` is "CSS classes".
- Shared value types live in `thallo-contracts`; core implements, packs consume; `composer boundaries` is a gate on every commit. Packs never import `Thallo\Core\`.
- `TemplatePolicy::CACHE_VERSION` is bumped with a `// bumped:` log line every time a Twig helper joins the allowlist. Starter count stays 47.
- New tables are registered in `packages/thallo-tenancy/src/ThalloTenantTables.php` (tenant column, widened uniques) and in `AppTestCase::TABLES` in the same commit; `ThalloTenantTablesTest` and `RawPdoScopingLintTest` stay green.
- Test gates one at a time (`COMPOSER_PROCESS_TIMEOUT=0 composer test`, ~10–15 min, never concurrent on `app_test`; `composer test:skeleton` and `composer test:distribution` also use `app_test` and never overlap the suite); phpcs judged by exit code; admin files formatted with `pnpm exec oxfmt <files>` only; `git diff` before every commit; no AI attribution trailers; never push, never tag (the split, the tags and the pushes are the user's).

## Shared contracts (named once, used by every slice)

Package `thallo-contracts`, namespace `Thallo\Contracts\Style` unless noted:

- `StyleCapabilities::all(): self` — every §1.3 path (new static on the existing class).
- `StyleClassRef` (final readonly): `id`, `style: array<string,mixed>`; `toArray(): array{id, style}` — the shape `CascadeResolver::resolve()` and `BlockStyleEmitter::classesFor()` already take as `list<array{id, style}>`.
- `StyleClassSnapshot` (final readonly): `generation: int`, `classes: array<string, array{id: string, name: string, style: array, archived: bool}>` keyed by id; `has(string $id): bool`; `refsFor(list<string> $ids): list<array{id, style}>` in the given order, skipping ids it does not hold.
- `StyleClassProvider` interface: `snapshot(): StyleClassSnapshot` (memoised until `refresh()`), `refresh(): void`. Bound by core to `StyleClassRepository`-backed `EngineStyleClassProvider`; consumed by the render pack (class layer, cache fingerprint) and by core's validator. `refresh()` is called at the start of every request that renders or validates, so a request works from exactly one snapshot.
- `SiteStyleGeneration` (core, rewritten): backed by a `style_generations` table with one row per site (`tenant_uuid`, `generation`), created lazily at 0; `current(): int` reads the row uncached; `incrementWithin(Connection $db): int` runs `UPDATE style_generations SET generation = generation + 1 WHERE …` and then reads the row on the same connection inside the caller's transaction (the updated row is locked until commit on every supported engine, so concurrent increments serialise and never both write the same value). The `SystemFlags` backing and `style.generation` flag are deleted.
- `DetachTransformation` (final, pure, in `thallo-contracts` because both core jobs and the render pack's tests use it; the TypeScript twin is `admin/src/style/detach.ts`): `detach(list<array{id, style}> $classes, array $instance, string $classId, StyleCapabilities $caps): array` — the §4.4 algorithm: resolve every property in `StyleSchema::properties()` the block has the capability for at every breakpoint (base only when non-responsive) with and without the class; where the resolution differs, write the previous resolution into the instance at that breakpoint (`reset` when the previous state was `reset`, the managed value otherwise); normalise by dropping empty maps. Fixtures `packages/thallo-render/detach-fixtures/v1/*.json` with the shape `{name, cases: [{name, capabilities, classes, instance, detach, expect}]}`; `expect` is the instance style after detach, compared as normalised JSON in both runtimes.
- Operations (TypeScript, `admin/src/editor/ops/types.ts`, already present and used verbatim): `ApplyStyleClass {block, class_id, index}`, `RemoveStyleClass {block, class_id, index}`, `ReorderStyleClasses {block, from, to}`, `DetachStyleClass {block, class_id, index, from_style, to_style}`, `InsertBlock {position, block}`, `MoveBlock {block, from, to}`, `RemoveBlock`, `DuplicateBlock`; `Position {parent, slot, index}` (root list: `parent: null`, `slot` the page's blocks field).
- Structure (TypeScript, new): `MoveIntent {block: string, to: Position}`; `Legality = {ok: true} | {ok: false, reason: LegalityReason}` with `LegalityReason = 'no-slot' | 'cycle' | 'depth' | 'type-not-allowed' | 'source-slot' | 'not-siblings'`; `DropZone {parent: string | null, slot: string | null, index: number, rect: {x, y, width, height}, layout: 'linear-vertical' | 'linear-horizontal' | 'other'}`.
- Error codes: `STYLE_CLASS_VERSION_CONFLICT` (409, `current_version`), `STYLE_CLASS_LOCKED` (409, `job`; also raised by a document write whose introduced references name a locked class), `STYLE_CLASS_NAME_TAKEN` (422 on `name`), `STYLE_CLASS_ARCHIVED` (422 when a document write introduces a reference to an archived class; references that were already stored stay valid so restores pass), `STYLE_GENERATION_STALE` (409 from an editor action that requires a fresh class list).
- Generation carriers: the apply response `style_generation`; the canvas page's `<main data-thallo-style-generation>` next to the epoch and revision; the bridge's `stage-refreshed {revision, style_generation}`; fragments' `style_generation`; the class-list response `{generation, classes}`. Every one is read from the snapshot the request rendered or listed from, never from a separate read.

Absent versus null in operations and DTOs stays `{present: false}` versus `{present: true, value}`.
